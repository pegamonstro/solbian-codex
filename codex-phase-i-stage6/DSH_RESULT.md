### Notes / deviations

1. **`--quiet`** suppresses only the banner; the report is always written unless
   the path is unwritable (then a warning goes to stderr).
2. **A/B/B′/C probe.** The check imports Stage 3's own `infer_plurality_flags`
   with `sys.dont_write_bytecode = True` so no `__pycache__` is left in Stage 3.
   It runs five synthetic labels and asserts the six catalogue flags stay
   distinct and that an ordinary law path does **not** acquire a catalogue flag.
   If the module cannot be imported, it falls back to source-level evidence.
3. **E4 is optional.** If the personae week `.sref` is absent, unreadable or
   below 280 characters, the check passes with a `SKIPPED: …` reason (documented
   in the report) rather than failing.
4. **Stage 5 store.** The suite only ever reads it (`mode=ro`) and re-asserts its
   sha256 is unchanged; the engine CLI always runs against a temp copy.

### What was built (staged)

* `app.py` — third surface, strictly read-only: `/api/engine/meta`,
  `/api/engine/facets`, `/api/engine/proposals`, `/api/engine/proposals/<id>`,
  `/api/engine/runs`; `POST /api/engine/dry-run`; 405 for every other non-GET.
  The Stage 5 store is opened with `mode=ro`. The dry-run copies the store to a
  temp dir, shells to `engine.py --db <tmp> run --dry-run`, shows stdout, deletes
  the copy, and re-hashes the real store to prove it is byte-identical.
  `--engine-db` / `--engine-py` (env `SOLBIAN_ENGINE_DB`, `SOLBIAN_ENGINE_PY`)
  make the store path configurable.
* `static/index.html`, `static/app.js` — the **Engine** tab: filter/search, paged
  proposal list, detail pane with body + `based_on` + provenance (resolved to the
  `source_document.rel_path`) + relationships, and a dry-run button. No canonical
  control.
* `smoke_ui.py` — boots the app against throwaway copies of the Stage 4 and
  Stage 5 stores; **96 checks** (all 61 original Solace/Codex checks plus 35
  Engine checks).
* `README.md`, `DSH_RESULT.md` — updated Stage 4 docs.
