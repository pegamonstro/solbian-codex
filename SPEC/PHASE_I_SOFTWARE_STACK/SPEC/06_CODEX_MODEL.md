# Codex Model

## Purpose

Represent Codex Solbian as a durable, browsable, versioned body of knowledge.

## Initial Structural Concepts

The implementation may represent:

- Codex;
- chapter;
- scroll or document;
- section;
- concept;
- principle;
- definition;
- question;
- relationship;
- revision;
- provenance reference.

These are conceptual categories, not a demand for an elaborate ontology.

## Existing Structure First

The existing Codex corpus should be inspected before a new taxonomy is imposed.

The software must not invent a complicated hierarchy merely because one is technically possible.

## Canonical State

Canonical Codex material must be:

- versioned;
- attributable;
- timestamped;
- reversible;
- traceable to sources.

## Read-Only Presentation

The primary Codex interface is a read-only inspection surface.

Editing should occur through the controlled consolidation process rather than arbitrary direct manipulation of displayed Codex content.
